# CLAUDE.md — Architect MUD

## What This Is

Post-singularity browser MUD in the HellMOO tradition. Text-driven, real-time, brutal, and funny. Node.js server with raw WebSockets, vanilla JS frontends (one HTML/JS file per client plus a sibling `styles.css`), PostgreSQL via Neon. No build step, no ORM, no framework.

### THOMAS and Architect are two different things

**THOMAS** — **T**he **H**ypermedia **O**nline **M**ultiplayer **A**dventure **S**ystem — is the **client and engine**. **Architect (Architect MUD) is one game built on it.**

The "System" is load-bearing: THOMAS is a *platform*, not this game's front end. With modification, and with the dev panel as the surface you'd do it through, somebody could build a **different MUD** on it. Roughly: `client/`, `server/engine/`, the dev panel, the plugin loader and the CODEX pipeline are THOMAS; the world in Postgres and under `content/` — Coldwater, the Basin, the orders, the prose — is Architect.

This is the existing "engine vs. content are separate" rule below, with a name and a reason attached. **The rule has teeth because of it:** anything that hardcodes Coldwater-specific content into an engine or client file is Architect leaking into THOMAS, and each leak is a thing a second game would have to unpick.

⚠ **Grepping for THOMAS misleads.** The only place the string appears is the dev panel's boot splash (`client/devpanel/index.html`, `client/devpanel/js/bootstrap.js`), which reads as if it names the dev panel. It doesn't — it names the platform the splash is booting.

- [plugins/cooking/README.md](plugins/cooking/README.md) — **cooking, as built**, and the doc to read before touching a dish. Beyond the 47-recipe catalog it now holds three rules worth knowing before you change anything: **boiling** — dry starch cooks in liquid, not in heat, so `cook` refuses a dry pan of pasta and `fill <vessel>` at a `water_source` puts `item_water` in the pan as an ORDINARY INGREDIENT ROW rather than as a second fluid-scalar representation nothing else would have understood; the `cooking_medium` tag is what keeps that honest — **a liquid for every question about the PAN (the starch gate, `hadLiquid`, boil-vs-sizzle) and invisible to every question about the DISH** (no cook session so it can never burn, no signature, no bands, no name), because without that split "penne and two bottles of water" is a valid pan of sauce again with a tap to make it free; **improvised dishes** (`improvised.js`) mean an unmatched pan is named off a family table rather than becoming slop — *food makes a dish, non-food makes a mess* — capped at `superb` so **`masterful` stays the authored catalog's alone**; and **player recipes** (`recipes.js`) are identified by their SIGNATURE, never their name, which is why renaming is free, one combination can only be saved once, and seasoning isn't part of the identity. - [docs/systems-mutations.md](docs/systems-mutations.md) — **mutations, as built** (Phase 1: the radiation half). Three rules carry the whole thing. **Expression, not a boolean** — every carried mutation has a 1-100 strength rolled ONCE at grant and only ever reduced by treatment, and everything downstream (soak, acuity, who can see it, what a clinic charges) derives from that one number; radiation deliberately cannot roll above 84, because a legendary rad mutation would undercut the reason to find the Wildblood. **Nothing is baked** — contributions are derived at read time and netted by the readers that already net gear and status effects, because the old model added stat_modifiers straight into `players.stat_*` and reversed the arithmetic to remove them, which is unrecoverable the moment one can be *partly* treated; the identity at expression 100 is a correctness invariant (it is what makes the migration net-zero on existing characters) and regress asserts it. **An authored effect key that nothing reads is now a BUILD FAILURE** — `effects` was authored on every mutation and read by literally nothing for months, so the vocabulary is a registry and an unregistered key fails the suite. Also: concealment is generic (a coat hides a torso mutation because it *covers the torso*, never because anyone wrote the coat into the mutation), detection is PER OBSERVER through `acuitySync`, `visibly_mutated` is now a write-through cache and **no longer a one-way latch** (treatment restores your standing, which is most of what the fee buys), and mutation body parts carry **zero hit weight** so unmutated combat is provably unchanged. Read the `bodyReport` trap before touching the paper doll, and the **deploy-order note** before shipping (the unbake one-shot runs BEFORE the code, or every stat is double-counted). **Phase 2 (the Wildblood half) is also built**: 24 mutagen mutations, the flask, the Quickening arc, natural weapons, active organs and enforced clothing conflicts. Three rules there. **A natural weapon IS a `weaponStats` object** — the same plain object a pipe produces, handed to the same `playerAttackEnemy`, so soak/crits/injury/body-parts treat a clawed hand identically and there is no parallel combat path; it returns `null` for an unmutated body, and it is consulted only on the UNARMED branch (pick up a pipe and you use the pipe). **An organ you cannot choose to fire is just a damage number**, so `shock`/`screech`/`morph` are verbs routed through the new `applyStrikeToEnemy` rather than passive modifiers — never write `enemy.hp` from a plugin, that skips the part roll, typed soak, damage observers and loot-on-death. And **a garment that does not fit is refused, never destroyed** — the body is the wrong shape, the coat is fine, and the way out is the `accommodates` tag carrying SHAPES (`TAIL`/`WINGS`/`CARAPACE`…) never mutation ids. The mutagen gate is enforced at `MUTAGEN_CONSUME`, the only path that spends a flask, and its refusals deliberately never name rep or flags. **Phase 3** adds `GRANT_MUTATION` (the authored VINE action — and it **re-checks the gate**, because an authored door is still a door) and the mutagen supply, whose scarcity is worth understanding before you "fix" it: the flask IS on a vendor's shelf, but that shelf is `min_trust`-gated on a numeric flag **nothing raises except the Quickening arc**, so it does not exist for anyone who hasn't been through the Pool. **Flight is mobility, not gravity** — the obvious reading of wings is falling slower and there is no fall-damage system to ride, so instead it reaches four seams that already exist: the ONE named exemption to `engine:impassable-terrain` (that gate's own comment always anticipated it, and it must never become a *gear* exemption — nothing purchasable opens a cliff), dry water crossing on the same path a boat uses, a flee-contest bonus, and the `swoop` dive attack. **Wings help you LEAVE a fight, never survive one** — the bonus is on the flee roll only and regress asserts `defenseBonus` is untouched. **Every effect key now has a reader and regress asserts the unconsumed list is EMPTY**; adding one without a reader needs a comment saying why plus the cap raised in the same commit. **Phase 4 closes the design's own gaps.** **Mutating is an INJURY** (`onset.js`, fired off the `mutation.gained` event every grant path emits): real HP that must be mended, most of your stamina gone up front, genuine weakness while it runs, scaling with expression and worse for mutagen — and **floored at 1 HP so it can never kill you**. That cost is what makes the Wildblood giving you a safe room for the Quickening a mechanic rather than a line. ⚠ **A regress suite that grants a mutation on the SHARED fake player must restore hp/stamina/statuses afterwards**, or the sneak and weightbench suites go red for reasons that look nothing like mutations. Three medical tiers at three prices: **diagnose** (a NAME, deliberately mechanically inert — an unseen mutation reads as "Something unnamed" until a physician names it, because a diagnostic that also *helped* would make not-knowing a penalty rather than an information state), **suppress** (temporary, reaches every contribution through the one `effectiveExpression` chokepoint, and reports as *held down* never as cured), **treat** (permanent, expensive). The social ladder (`reactions.js`) is **socially hostile long before it is physically hostile** — there is no "mutant = attack" rule and regress asserts none of its lines is violence — and it **never fires in the Scarletwastes**, a hard region check, because a town that recoiled from its own people would break the one thing the region is for. `clone_inheritance` defaults to `all`, which is exactly the behaviour that already shipped
- [docs/systems-nullcraft.md](docs/systems-nullcraft.md) — **Nullcraft, the Null's discipline** (Phase 1 as built): the fourth faction answer, where the Ascendants buy a better machine and the Null make somebody else's stop working. The rule that shapes all of it: **it never invents a second copy of state that already exists** — a surprising amount of this was already shipping camera-scoped and scattered (`security_devices.status_flags` has held `{jammed, spoofed, hijacked_by, looping, blinded}` since forever, `getInterferenceZones` already jammed zones, `isWitnessed` already read it), so this is a PROMOTION of that model onto bionics/drones/locks, not a new one. Three more decisions carry it. **Trace is RAM-authoritative and decays at read, never on a tick** — the engine file owns no table, a logout drops everything, and only durable damage persists, through the CONTRIBUTOR's own writer. **Targets arrive by gather hook** (`tech.targets`, the `workspace.provider` seam), and `apply()` lives on the target, which is what keeps the substrate free of imports from augments and surveillance — the integration is ONE line in `deviceStatus()` and ONE filter in `getAugments()`, so every downstream reader inherits Null jamming without knowing it exists. **Security is derived, never authored twice** — `overclock_max` does double duty, since it is already the whole mechanical statement of the faction split, making licensed chrome the hard target with nothing new authored. Read the applicability table before adding an operation (you cannot jam a hydraulic ram; collapsing that makes six operations one verb with six skins), the **telemetry-is-not-vital** rule, and `VEIL_CAP` — ghosting must never make a player unarrestable. Architect's network ladder is **design only**
- [docs/systems-psionics.md](docs/systems-psionics.md) — **Psionics, the Exodus discipline** (Phase 1 as built: psychometry + telekinesis). The fifth faction answer, and the one whose promise was prose only until now — the ideology row already said they *"still a room and move what is in it without a touch"*. Three rules carry it. **Deniability is the progression** — codex XIV deliberately leaves psionics unconfirmed ("the Basin's favourite joke") and Terminus rules that stating a thing kills it, so below Seer **no output line may claim a mechanism** and at Seer the prose may be impossible; the player crossing that line IS the arc, and the law lives in ONE function (`voice()` in `prose.js`) with a `violatesLowRank()` regress seam, because a law spread across forty template strings is a wish. **The body pays** — the mind is doing something the body was not built to support, so strain is a ladder of nosebleed → blood from the ears and failing sight → **seizure** (`knockOut`, the cosh's own seam, so you are killable where you lie) → **real damage through `applyStrikeToPlayer`**, which makes the injury plugin's observers hang an actual wound off it rather than this file authoring one; nothing invents a punishment, and the backlash ladder IS the deniability ladder, which is why it broadcasts to the room. **Psychometry reads the world's own exhaust** — `residue.js` subscribes to events that ALREADY fire into a decaying per-zone ring buffer, no other system was modified to feed it, and an impression is fragmentary and **unattributed forever** (cameras answer WHO; this answers WHAT HAPPENED HERE and sends you to find out who, which is what stops it deleting SPECTER). Also: **you major in one art and minor in another** — `psi_rank` is depth and `psi_focus` is breadth, top abilities are `focusOnly` and unreachable off-major at ANY cost, so there is no build that both takes bodies and walks dreams; resistance is **derived** from Cool/Brains/mastery/Static Mind/coprocessor with deliberately no second skill; and `PSI_CAP` is `VEIL_CAP`'s sibling. Read the **verb-collision trap** before adding a verb (it cost three renames: `attune` and `pull` are engine builtins, `read` is a specializedAction in six plugins, and plugin commands silently beat both classes — checking `plugin.json` command arrays is NOT sufficient), and the rule that `reach` fires `fireSpecializedAction` so **telekinesis always delivers existing verbs rather than reimplementing them**. Telepathy, precognition, biokinesis, projection/**dreamwalking**, compulsion, the Gate Keeper's Purifier and the armour taboo are **design**

- [docs/systems-trucking.md](docs/systems-trucking.md) — **THE LONG HAUL: driving the void** (phase 1, bobtail, as built). The road between regions as something you drive rather than endure, and three rules that are each a decision NOT to build something. **The corridor synthesises ZONES, never render cells** — `corridorAt` returns the shape `surfaceAt` returns and hands it to the flight sim's `mapWindow` through its new cell-provider parameter, so road auto-tiling, biome, buildings and fog come from the one derivation that already exists (`snapshot.js` kept its own copy and drifted twice, silently losing 144 street tiles and then park features; both now share `deriveSurfaceCell`). **The drive IS the crossing** — `current_zone` stays the void room and a node boundary emits `zone.entered`, so voidwalking's encounters, traces, hard nodes and teardown are triggered here and implemented nowhere here, and a breakdown finishes on foot for free. **The edge of the road is a law, not a wall** — no ground collision at all; the verge is slow and past the half-width you are bogged, never blocked. **The road BENDS, and the bend is a heading rather than an icon** — the corridor was a polyline of axis-aligned legs that needed no steering at all; it is now a curve, and the three rules in §1b are each a way that goes wrong silently. **The minimum turn radius is a correctness invariant**: cells are classified by distance from the centreline out to `OFFROAD_R`, so a bend tighter than that folds the verge band through itself and the odometer jumps backwards through the fold. **The tarmac had to get wider** — a one-tile band is fine on an axis and comes apart on a diagonal, where tiles touch only at their corners and the highway renders as a dotted line of squares (regress flood-fills the paved set demanding one 8-connected piece). And **the leash is applied when a bend is CHOSEN, never while one is driven** — pulling the heading back toward south every tile is the obvious way to write it and means the *straights* are not straight either, so no bend registers as an event because everything is one. Read the **explicit-road-icon** rule before touching `corridorAt` (the auto-tiler ORs adjacent road cells, so an unauthored corridor paints a crossroads for the entire length of the highway — the icon is still authored, but only ever as the nearest axis, never as a bend piece; the real direction ships as `road_deg`/`road_t`/`road_w`), the **surface tuning invariant** (`thrustMax × drive > rollFric × drag`, or the verge becomes a wall wearing a penalty's clothes), and the note that **the client reports where it IS, not how far it has come** — the server derives the odometer from position against its own geometry, because a self-reported distance lets a client weave and get paid for the tarmac. The cab is `paintWindshield` with `height: 0`; the wheel is `helm-wheel.js` in a new `absolute` mode (a boat sets a course, a truck holds a line). Phasing and the unbuilt half — gearbox, trailer articulation, the yard, the weigh station that detects **weight, not contraband** — are in [proposals/the-long-haul.md](docs/proposals/the-long-haul.md). Later: **the junction is a fork you can SEE** — a route is a trunk plus ONE limb because that is all the odometer runs along, so `corridorAt` only ever asked that road what was at a tile and the highway visibly ENDED in open waste at the fork; a route now carries its siblings and falls through to them, with ⚠ `corridor_s`/`corridor_node` STRIPPED from a sibling cell (a cell handing out another limb's odometer is wrong in a way that looks right) and the siblings built without a plan of their own, which both terminates the recursion and leaves them signless. And **the road signs itself**, in MILES — one conversion (`TILES_PER_MILE`) shared by the board, the `route` verb and the GPS, because a board saying 240 while the dash says 720 means nobody can budget a tank. Three rules there: **a sign is one TILE snapped at build time** (a tolerance band, which is right for a shed, renders a post as four identical boards in a row); ⚠ **the junction board looks 210 tiles PAST the fork**, because at an ordinary look distance the limbs have separated by ten degrees and it points every one of them straight on; and **passing a board is a SWEPT range**, never "am I near one", since the cab reconciles 4×/sec and a text tick covers a slab of road. The board is a `mark`, not a `building_type` (a building enters the collision sweep, and a sign that stops a truck is not a sign), and its rows reach the LOG as prose too (as built)

A domain-agnostic `plugins/workspace/` fed by the `workspace.provider` gather-hook plus **two providers** — `kitchen` (`plugins/cooking/workspace.js`) and `chembench` (`plugins/synthesis/workspace.js`), the second added with **no change to the workspace plugin or its client panel**, which is the seam proved rather than asserted. The rule that shapes it: **the HUD holds no gameplay logic — every action is a verb string a player could have typed**, which is why the payload ships literal commands rather than opaque ids and a regress case sweeps every one against the live verb registries. Provider gates are **coarse on purpose** — the HUD proposes, the verb decides; re-deriving a verb's real preconditions in the provider is the duplicate implementation this whole layer exists to avoid. The **Recipe Assistant scores only recipes the player KNOWS** — listing the undiscovered half with exact shortfalls is the ingredient checklist the Cookbook app deliberately refuses to be, and it would kill discovery. Read the **reservation** section before adding any soft-lock: nothing in the game locks an inventory row (trade explicitly refuses escrow), so `prepare <recipe>` is a re-validating plan, not a claim — it walks ordinary commands, stops on the first failure, never answers a SIFT prompt, and **stops at a loaded vessel without cooking**, because heat is where the skill is
- [docs/systems-cards.md](docs/systems-cards.md) — the **portrait** renderer for the same cards: per-piece vector art on a body silhouette, `{body,item_ids,seed}` stored rather than an image. **Still unwired** — the text face is what ships, and an enemy card can never use this one. Not debt; a second face the card view could grow

**Before touching any system, read the relevant doc section if there's one applicable to the request.**

**Before editing any player command, check [docs/plugins.md](docs/plugins.md) first** — a plugin may already own that verb, in which case the engine handler for it is dead code.

## Core Architectural Rules

- **Engine vs. content are separate.** The codebase is the engine. World content (zones, items, enemies, NPCs) lives in Postgres and is edited through the dev panel. Don't hardcode content into engine files.
- **No ORM.** All queries go through the single `query()` helper in `server/models/db.js`. Keep it that way.
- **No startup migrations. Schema and content are managed deliberately, never on boot.**
    - **Schema** is the single source of truth in `server/models/schema.js` (`SCHEMA_SQL`, idempotent DDL). `npm run db:schema` applies it to your **local** dev DB. Production gets it through the CODEX deploy (below), not a manual `db:schema` against prod.
    - **Content lives in git (CODEX pipeline).** World content is one JSON file per entity under `content/`, and a **fresh database is built with `npm run db:create-local` (empty DB) → `npm run content:import`** (which applies `SCHEMA_SQL`, then loads the content tree). There is no checked-in `seed.js`/`seed.sql` and no boot-time content rewriting (the old startup `migrate()` was removed precisely because it disrupted dev by mutating content on every restart). The dev-panel `.sql` export (`/dev` → Power Tools → _Database Backup_) + `npm run db:restore -- dump.sql` remains as a **self-contained-SQL escape hatch** (backups, recovery), not the primary seed path.
    - **CODEX is the deploy path (git as source of truth).** World content lives as one JSON file per entity under `content/`; a push to `main` is the deploy — CI applies the full `SCHEMA_SQL` ahead of the additive content, backs prod up first, and is regress-gated. So idempotent schema DDL (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, deferrable-constraint swaps) **and** new content both reach prod through a normal push. See [docs/content-pipeline.md](docs/content-pipeline.md) and the `codex` skill for the authoritative flow.
    - **To change the schema:** edit `SCHEMA_SQL` (idempotent), apply locally with `npm run db:schema`, and ship to prod via the CODEX deploy (push to `main`). Never an auto-run boot migration. **Reserve manual one-shot scripts for what the deploy genuinely cannot do**, which is narrower than it looks. **The deploy DOES rewrite existing rows**: for any table with non-PK columns the import is `INSERT … ON CONFLICT (pk) DO UPDATE SET <every file column>` ([import.mjs](scripts/content/import.mjs) — `DO NOTHING` is only the branch for PK-only tables). Because a whole column is replaced, **editing a content file is enough to REMOVE a JSONB key** — dropping `flags.utility_room` from `content/zones/*.json` cleared it from 79 prod tiles with no script at all. So a one-shot is only needed when the new value **cannot be derived from the files**: reading state the files don't carry, or writing a table the pipeline doesn't own. (Corrected 2026-08-02 — this paragraph previously claimed the deploy "can never touch existing rows", and that sent two unnecessary one-shots at prod.)
    - **Running a one-shot against prod:** `node --env-file=.env.prod scripts/<name>.mjs` (the git-ignored `.env.prod` holds the prod `DATABASE_URL`). `db.js` enables SSL by **host** — remote ⇒ TLS, localhost ⇒ none — so this needs no `NODE_ENV` juggling and any `query()`-based script works against prod this way. Omit the flag to go back to local.
    - The export deliberately excludes player/runtime rows (accounts, inventory, password hashes); it carries schema + world content only.
- **Plugins for extensibility.** New behavior hooks belong in `/plugins/`, not in engine files, unless they're genuinely core.
- **No new sparse columns on `players` (or `npcs`).** New per-player scalar state goes in `player_flags` or its own feature table — never another `players` column. Same for per-tick/derived state: check the persistence tiers in [docs/architecture.md](docs/architecture.md#persistence-tiers-when-to-write-the-db) before adding a runtime DB write.
- **Every `query()` is a remote round trip — decide the read tier before adding one.** Prod Postgres is remote; latency lives in round-trip _count_, not query cost. Check the [read tiers in docs/architecture.md](docs/architecture.md#read-tiers-where-data-lives-at-runtime) before a new feature reads the DB: hot paths (per-move/per-swing/per-tick) never add awaited queries — serve them from the live player object, the world Maps, or a cache tier; never query in a loop (`id = ANY($1)` / `GROUP BY`); `Promise.all` independent reads; coalesce same-row writes; idle-gate scheduled ticks on `hasActivePlayers()` and register them via scheduler.js. **A cache is only as safe as its write funnel — grep every writer before caching a table** (why `furniture` and `npcs` rows are deliberately uncached).
- **UTF-8, always.** Several files (especially `client/game/index.html`) use Unicode glyphs and box-drawing chars (`₵ ⚙ ⏻ ╱ █ ☢`). When editing, preserve UTF-8 without a BOM — never let a tool re-save as Windows-1252 or it double-encodes everything into `â•±â•²` mojibake. After editing such files, sanity-check that the glyphs are still intact.

## Regression Testing — run it, and recommend it

`npm run test:regress` ([tests/regress.js](tests/regress.js)) is the pre-deploy gate. It boots the
world + all plugins (no server), sweeps every plugin manifest against the live registries (declared
commands/hooks actually wired), then drives real commands end-to-end through `handleCommand` with a
fake player — dispatch order, posture, move gates — plus every plugin's own `regress.js` suite.

**Run it without being asked** after any of these, and say so in your summary:

- editing the dispatch pipeline (`commands/index.js`), plugin loader, or any engine registry/seam
  (actions, events, hooks, specialized actions, move gates, posture)
- adding/removing/renaming a plugin verb, or changing a `plugin.json`
- extracting or relocating a system (engine↔plugin moves)
- **before any deploy/push of server code** — recommend it even for changes that look unrelated

Never wire it into production boot (same principle as no startup migrations — boot stays deliberate).

**When you add a plugin or a verb, add a `plugins/<name>/regress.js`** (default-export
`async ({ run, check, getPlayer }) => { … }`; see [plugin-standard.md](docs/plugin-standard.md)).
Test code lives with the plugin and never loads in production.

Caveats: it shares the Neon session pool (pool_size 15) — if it dies with `EMAXCONNSESSION`,
an orphaned local `node server/index.js` is holding pool connections. A `pretest:regress` hook runs
`scripts/kill-orphans.js` to sweep these automatically before every regress run (and `predev` does
the same before `npm run dev`); run it by hand any time with `npm run kill:orphans`. It's Windows-only,
scoped to this repo's own entrypoints (`server/index.js`, `tests/regress.js`, `sync-commits.js`,
`scripts/dev.mjs`, `tools/studio/serve.mjs`), and
never runs in production (`npm start` has no pre-hook). If a sweep can't reach it, wait ~90 s. Player
stat columns are `stat_brawn`/`stat_reflexes`/… (not `brawn`).

`pretest:regress` also runs **`docs:lint`**, which is **three checks**, not one — and the hook now
invokes the npm script rather than one of its files, so there is a single definition of what doc
linting is. (It called `scripts/docs/lint.mjs` directly until 2026-08-14. The two read identically in
prose — "docs:lint runs" — so `docs:verbs` and `docs:links` were never gated at all, and a real gap
sat behind that wording for months. If you add a fourth check, add it to `docs:lint` and the gate
picks it up.) The three: **`docs:links`**, which fails when a doc link does not resolve;
**`docs:verbs`**, which fails when a plugin verb is not named in [docs/plugins.md](docs/plugins.md)
(a verb a player can never type — a client handshake like `readresolve` — goes in `NOT_PLAYER_TYPED`
in [scripts/docs/verbs.mjs](scripts/docs/verbs.mjs) *with a reason*); and
[scripts/docs/lint.mjs](scripts/docs/lint.mjs) itself, which fails
when a doc's **status header contradicts its own body** — a header asserting nothing is built
("Not Yet Built", "Nothing here is implemented", "DESIGN ONLY") sitting above a body full of ✅/`*Built:*`
markers. This exists because on 2026-07-27 an audit reported five shipped systems as outstanding work,
every error traced to a stale status line; `systems-weather-extreme.md` was titled "Design — Not Yet Built"
above a roadmap complete through step 7d. **A compound status is fine and is NOT flagged** — "Phases 0–2
built; rest design" or "STATUS: BUILT (design intent below)" pass, because mixed status is the normal case
for a living system. When you finish a system, update the line at the TOP of its doc, not just the roadmap
at the bottom.

`pretest:regress` also runs **`content:lint`** (and a `precontent:import` hook runs it before any
`npm run content:import`), so a hand-authored content file carrying a runtime column — an
`excludeColumns` key like `zones.stains` — fails locally instead of surviving to the CI deploy gate.
Both mirror the CI order (lint → import → regress). `content:export` already strips those columns, so
only hand-written files can trip this.

`pretest:regress` also runs **`shapes:smoke`** ([scripts/shapes/smoke.mjs](scripts/shapes/smoke.mjs)),
which executes all ~83 flight-sim building models in `drawTypeModel` (`client/game/js/panels/windshield.js`)
against a DOM stub — night and day, both entrance facings — and fails if any of them throws. This is
the ONLY automated coverage the windshield has. It exists because the only thing that ever ran a
building model was a player flying past that particular building: the Battery Acid Coffee Co. roaster
passed a palette KEY where `drawFacetDrum` wants a style FUNCTION, and it froze the whole sim mid-frame
the first time that cafe came into view. It also gates the shape-capture data (geometry must stay
affine in the footprint/height arguments). **Run it after touching any building model or mass
primitive**; it needs no browser, DB or network and takes about a second. If it fails on a browser API
rather than a real bug, add that API to [scripts/shapes/dom-stub.mjs](scripts/shapes/dom-stub.mjs).
It proves models RUN, not that they look right — there is no pixel comparison.

`pretest:regress` also runs **`client:smoke`** ([scripts/client/parse-smoke.mjs](scripts/client/parse-smoke.mjs)),
which parses all ~194 files under `client/` and fails if any one of them is not valid JavaScript.
There is no build step, so before this nothing between an editor and a player's browser ever parsed
them, and the existing smokes only import the specific modules they exercise. **The failure it exists
for is the backtick.** Client panels are big HTML template literals, the house style writes long prose
comments inside them, and the house style quotes verbs in `backticks` — so a comment ends the string
mid-sentence. A `` `horn` `` in a `<!-- -->` note in `cab-view.js` killed the entire client boot on
prod (`main.js` reaches every panel transitively: chrome rendered, then no room, no vitals, no socket).
**Inside a template literal, quote identifiers with 'single quotes', never backticks.** One note on the
check itself: it feeds each file to `node --check` on **stdin with `--input-type=module`**, because
plain `node --check <path>` parses a `.js` in the CommonJS goal and *passes* that exact broken file.
Don't "simplify" it to a path argument. Takes ~2 s, no browser, DB or network.
