What changed since the first edition01

The first edition of this report was published this morning. By this afternoon, five of its twelve outstanding-work items had been struck — not because they were fixed, but because they were never true. Every one of them came from the same failure: reading a status header instead of the code underneath it.

The pattern, stated plainly: the doc bodies were accurate and the doc headers were not. systems-weather-extreme.md was titled "Design — Not Yet Built" with "nothing here is implemented" sitting directly above a roadmap where every step through 7d was marked ✅ with implementation notes. The void-travel memo opened "DESIGN ONLY, nothing built" above fourteen shipped slices. Nobody updates the top of a file they're appending to the bottom of.

The reassessment02

Correcting the ledger changes the diagnosis. The first edition described a project with an excellent foundation and a long tail of half-finished systems. That second half was mostly an artifact of stale prose. What the corrected picture shows is a project that finishes things — weather went to 7d including presentation, void travel went to six slices including a frontier map and ghost-traces, and both did it without anyone updating the summary line.

The structural facts from the first edition all survive verification, because those were measured rather than read. Plugins still outweigh the engine two to one, which means the engine/plugin boundary is real rather than aspirational. The client is still the largest body of code in the repo. Content still lives in git behind a regress-gated deploy.

What the audit itself cost

Five wrong findings out of twelve is a 42% error rate on the qualitative half of a report whose quantitative half was sound. That asymmetry is the useful lesson: the numbers were right because they were counted, and the assessments were wrong because they were quoted. A status line in a doc is a claim with no test behind it, and this codebase has 3,079 tests and 24,669 lines of prose. Only one of those two numbers is verified on every push.

Where we genuinely stand03

Verified strengths

The engine is small and the systems are outside it. Substrates — durability, relationships, hygiene, senses, cleaning — are sync and query-free by contract, so an NPC recalling your face or a rifle degrading mid-swing costs no round trip. Content is one JSON file per entity in git, and a push is the deploy: schema first, content additively, backed up, regress-gated. Weather, void travel, the sports pipeline, flight, and the crime/jail loop are all complete systems rather than scaffolds.

The three that actually matter

  • Content depth, not content mass. This was the first edition's finding and it is the only one that got stronger under scrutiny. Every system that could give a player a reason to walk somewhere is built. What's thin is the reasons themselves — NPCs, quests, enemies. The next expansion pass should not be a map.
  • The manual post-deploy step. A deploy that isn't finished until a human remembers to run a script against production isn't a deploy, it's a ritual. Everything else in the CODEX pipeline is automated and gated. This will eventually ship a city with the lights off.
  • Status prose has no test. Newly promoted, on today's evidence. The codebase gates code on every push and gates content on every import, and lets a doc header claim a shipped system is unbuilt for weeks. A docs:lint that flags any header saying "not built" above a body full of ✅ would have caught every error in this report.

In conclusion04

Thirty-nine days, a quarter of a million lines, and a city that has weather that can kill you by name, a walkable void between regions, two sports leagues, and a public library restricted to expired copyrights. The foundations were reported as strong this morning and they remain strong this afternoon; what changed is that the list of unfinished things turned out to be a list of things nobody had written down as finished.

That is a better position than the reverse, and it comes with a cheaper fix. The engineering discipline here is real — 3,079 tests, a gated deploy, substrates that hold their contracts. The documentation discipline is real too, in the bodies of the files, where the ✅ marks are meticulous. What's missing is the thirty seconds at the end of a system's last commit when someone goes back to the top of the file and changes one line.

The state of the game is strong. It has been strong for some weeks. Somebody should have said so at the top of the file.
