◆ Relay — the code lane changed

Two hands on one push — Relay stashed, and the tree tore. Now git alone gates.
Thanks, Akerson. You were right — you called out that Relay got messy during simultaneous pushes: it would stash, pull, shuffle the working tree, and clash with edits you already had open. That was a real design flaw, not you holding it wrong. So we fixed the root cause instead of papering over it.

What was actually wrong

Relay was a second hand on the same git working tree as your terminal — it fetched on a timer and its "Ship code" button did its own commits/pushes. When two of us pushed at once, that second hand would stash-and-shuffle to get out of its own way, and your uncommitted work got caught in the churn. The only thing that button really added over plain git push was the regression gate. Everything else was just git — fighting the git you were already running.

The fix

The regression gate moved into a pre-push git hook. It now runs no matter how you push — terminal, Relay, IDE — and it can't race your terminal, because it is part of the push, not a separate tool poking the repo. Relay no longer pushes code at all. No more stashing. No more clash.

Code → plain git

Commit and git push like normal. The hook runs regress and blocks a red push automatically.

World → still Relay

Content (the shared DB seed) stays in Relay — ⇧ Publish / ⇩ Sync. That's the part worth a button.

What you do now

1

One time — turn the gate on in your clone:

npm run hooks:install

This points git at our shared hooks. Do it once per machine. (If your Recent activity already shows commits, you've probably done it — running it again is harmless.)

2

To ship code — just use git:

git add -A git commit -m "what you did" git push

On git push the gate runs the full regress suite. If it's green, the push goes. If it's red, the push is blocked and it tells you what failed — nothing leaves your machine until it's fixed.

Pushing only world content (db/seed.sql, i.e. a Relay Publish) skips regress automatically — there's no code in it to test.

3

To ship world content — Relay, same as always:

⇧ Publish content to share your local world; ⇩ Sync content to pull mine. Unchanged.

4

Relay's Code card is now a pre-check, not a pusher.

It shows the pre-flight lights (ahead/behind/dirty) and a ▶ Run regress button if you want to test before you commit. The old ⇧ Ship code button is gone — that's the whole point.

Emergency escape hatch: if the gate ever wrongly stands between you and a push you truly must make, git push --no-verify skips it. Use it only when you mean it — it's the one door around the safety net.

If a push gets blocked

  • Read the failure — the hook prints which regress checks went red. Fix them and git push again.
  • "EMAXCONNSESSION" / pool errors → an orphaned local server is holding DB connections. Run npm run kill:orphans, then push again.
  • Diverged / behind → pull (or Relay ⇩ Sync) first so your push fast-forwards, then push.

Same idea as before — just git / npm with a safety net — except the net now lives inside the push instead of beside it. Thanks again for the nudge that got us here, Akerson. — Cyd
