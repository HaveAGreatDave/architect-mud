## How to run the next pass

The method that worked for both passes, rather than editing files one at a time:

1. Extract every em dash with ±28 characters of context, keyed on that window, and dedupe. Repeated
   boilerplate collapses hard — pass 2 went from 1270 raw occurrences to 1112 unique spans, and many
   of those shared a prefix that one patch could cover.
2. Rewrite each unique span into a `[index, old, new]` patch table.
3. Apply by plain string replace across every candidate file, and **fail loudly on any patch that
   matches nothing** — a silent miss is how a half-swept file happens.
4. Re-scan to zero, then run `content:lint` and `test:regress`.

Patches are ordered, so put specific spans before generic ones (`" — please welcome {host}!"` must be
listed above `" — {host}!"`).

The replacement is almost always already in the sentence: comma for an appositive, colon for a list,
full stop where a second thought lands hard, paired commas for an aside, ellipsis for an interruption
or a trailing-off. Never trade a dash for ` - `, ` -- `, or an en dash — that is the same tic wearing
a hat.
